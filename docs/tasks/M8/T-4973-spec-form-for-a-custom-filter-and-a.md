## Goal
The eval spec `"criteria"` form can write a custom filter and a display-text values list, so the T-4895 and T-4939 uploads become eval cases.

## Context
T-4965 left these filters as research sidecars (docs/research/t4895/uploads, docs/research/t4939/uploads) because spec_tables.py and the eval adapter (add_table in crates/rustsheet-eval/src/engine.rs) cannot express them.

## Acceptance criteria
- [ ] spec_tables.py and the adapter accept a custom filter and a display-text values list.
- [ ] The uploads are probes cases with their oracle values.
- [ ] `make check` green; reviewers approve.

## Out of scope
- New filter semantics; other operators stay unprobed.

## Outcome
Spec `criteria` entries take `values` (listed display text) or `custom` (`and`, `conditions` of operator/val): spec_tables.py writes them, the adapter applies them through the new `Txn::filter_table_column_values` / `filter_table_column_custom` (engine `Model::set_table_filter_criterion`). The four uploads (custom, custom-upper, display-control, display-delete) are probes cases with their oracle values, generated by docs/research/t4895/gen.py. Eval: +4 probes cases, 71 cells checked, all pass; custom-upper's F!A6 (COLUMNS) is left unchecked because Excel read 3 columns there (delete not applied), noted in docs/excel-semantics/numbers.md.

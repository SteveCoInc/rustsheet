## Goal
`rustsheet-accuracy math` writes the same sidecars on any machine for the same inputs, as `write_suite` claims.

## Context
- tools/src/rustsheet_tools/accuracy/tables.py `TIME_LIMIT = 10.0` drops a point whose `compute()` takes more than 10 s
  of wall-clock time.
- On 2026-11-01, regenerating probes-numeric for T-3529's merge dropped
  probes-numeric/t3350-r4-chisq-inv-sweep Calc!A237 (`=CHISQ.INV.RT(0.999999999962187,9123239)`). A faster run had
  written it (9095462.568446318...). The commit restored the earlier output by hand from git, since the case is
  unchanged. A second run under load the same day dropped t1531-t-tiny-p Calc!A106 (`=T.INV.2T(1E-300,100000)`)
  the same way.
- A machine-dependent drop silently unchecks a cell against the math, and it makes sidecars differ between runs.
  Gate A table batches use the same limit.
- Gap triage 2026-11-03: four visibly-off BETA.DIST cells that no task owned are `skipped` with "not converged or too
  slow" in probes-numeric/t3571-r5-bfrac-fresh.math.json, so R1(c) counts them for want of a math value. This task
  owns them until they have one:
  - probes-numeric/t3571-r5-bfrac-fresh.case.json (4): Calc!A239, A441, A902, A978
  - e.g. A239 `BETA.DIST(0.583019617141068,4563.6,2816.5,TRUE)`: Excel 3.0490854915703563e-10, ours
    3.0490854915703785e-10. T-3813 (deferred) studies these shapes' bfrac rounding. If they are inside Gate A's
    envelope once they have a math value, they become Phase 1b evidence. If not, file their engine owner.

## Acceptance criteria
- [x] Points are dropped by a deterministic budget (iterations, terms or precision steps), not wall-clock time; or the
      limit is generous enough that no committed point is near it, with a test that pins A237.
- [x] Regenerating probes-numeric twice on different load changes no byte.
- [x] t3571-r5-bfrac-fresh A239, A441, A902 and A978 get a math value (a larger deterministic budget for the incomplete
      beta at shapes near 5000), or their skip reason is deterministic and the Outcome names an owner task for them.
- [x] `make check` green; reviewers approve.

## Out of scope
- Speeding up the incomplete-gamma series.

## Outcome
- `rustsheet-accuracy math` and the Gate A table batches no longer drop a point by wall clock. `tables.compute`
  keeps a 600 s hang guard that stops the run (`PointTimeoutError`) and never drops a point. Points are dropped
  only by deterministic budgets: `model.work_budget`/`model.spend` (2M summed-expansion terms per precision,
  charged by the incomplete-gamma series and continued fraction), mpmath's own `maxterms`, and the incomplete
  beta's term budget (`defs/beta.py`: mpmath's `betainc` up to a + b = 2E4 with a positive-term
  2F1(a+b, 1; a+1; x) series where mpmath gives up, the series alone above 2E4, mpmath alone above a shape of 1E7).
  The skip reason "not converged or too slow" is now "not converged"; SPEC-0029's Precision bullet matches.
- AC2 (same bytes on any load): probes-numeric was regenerated by two runs at load 7 to 10 (398 cases
  byte-identical between them) and the rest once; probes was regenerated with 4 workers at idle load in this
  session: 2408 of its 2455 spec cases came out byte-identical to the committed sidecars. t3505-gamma-inv-budget-band
  was the only sidecar still holding clock skips (170 "not converged or too slow"); regenerated, it holds 285 math
  values (77 new, 0 changed, 0 lost) and 93 deterministic "not converged" skips. t3007, t3350-chisq-inv-huge-df and
  t3352-binom-negbinom-large-n were regenerated from this code by earlier runs of the task. Changed sidecars against
  main: t3960-binom-negbinom-small-p-cdf 266 -> 300 math values and its hold case +15, the t3443 basym cases, and
  t3571-r5-bfrac-fresh (below); no math value already on main changed. `math --check --suite probes --suite
  probes-numeric`: current. A full probes regeneration takes several hours on 4 cores, dominated by the huge-df
  CHISQ.INV/GAMMA.INV searches that now run to their budget instead of stopping at 10 s.
- AC3: t3571-r5-bfrac-fresh A239, A441, A902 and A978 (and A426, A638) have math values. All six are inside Gate A's
  math envelope (1e-9 relative): ours is 2.9e-15 to 2.1e-14 relative from the math, Excel 5.9e-16 to 3.3e-14
  (A239: Excel 5.3e-15, ours 1.25e-14). So they are Phase 1b evidence under R1(c), and need no engine owner.
- Eval delta: no case verdict changes (math sidecars only attach references); R1(c) visibly-off cells without a
  math value shrink by the new math values above.
